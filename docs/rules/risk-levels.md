# 风险分级定义

> 被 `~/.claude/CLAUDE.md` 引用。所有等级均需评审和批注（红线），区别在于流程深度。

---

## 低风险

**定义**：不影响运行时行为的变更。

**示例**：
- 文档、注释、README 修改
- 代码格式化、import 排序
- 日志文本调整
- 配置文件中的非功能性字段

**流程要求**：
- 需求细化：可简化，一句话确认即可
- 方案设计：简要说明改什么、为什么改
- **评审：必须**（红线）——但验证方式可简化为"确认你看过这个变更"
- AI 自审：可省略
- **批注：必须**（红线）——可以简短，如"确认，文档修正"

---

## 中风险

**定义**：影响运行时行为但范围可控的变更。

**示例**：
- 新增功能代码
- Bug 修复
- 单元测试 / 集成测试修改
- 非核心模块的重构
- 依赖版本升级（非 major）

**流程要求**：
- 需求细化：完整执行
- 方案设计：完整执行，含文件清单、技术方案、风险评估
- **评审：必须**（红线）——完整验证理解（见 review-protocol.md）
- AI 自审：必须执行
- **批注：必须**（红线）——需要对关键变更点逐一批注

---

## 高风险

**定义**：影响安全性、数据完整性、或生产环境的变更。

**示例**：
- 认证 / 授权 / 加密相关代码
- 数据库 schema 变更、migration
- 生产环境配置（CI/CD、部署脚本、环境变量）
- 核心业务逻辑（支付、订单、权限）
- 依赖的 major 版本升级
- 删除或重命名公共 API

**流程要求**：
- 需求细化：完整执行，**必须明确回退方案**
- 方案设计：完整执行，**必须包含备选方案对比**
- **评审：必须**（红线）——完整验证理解 + **要求用户解释方案对既有系统的影响**
- AI 自审：必须执行，**额外检查安全性和向后兼容性**
- **批注：必须**（红线）——需要对每个文件的变更逐一批注
- **额外要求**：建议在独立分支上执行，提交前运行完整测试套件
