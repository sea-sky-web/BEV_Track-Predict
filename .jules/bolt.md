## 2026-06-17 - PyTorch Perspective Warp and Parallel Processing Optimizations
**Learning:** For PyTorch grid sampling and perspective warping in this architecture, using `float32` coordinate arithmetic combined with `torch.bmm` is highly performant. Furthermore, out-of-bounds handling should leverage `F.grid_sample`'s native `padding_mode="zeros"` by simply pushing invalid coordinates out-of-bounds (e.g., `invalid = z <= 1e-6; coords = torch.where(invalid, 2.0, coords)`), which avoids the significant overhead of complex arithmetic penalties or mask-filling operations like `torch.nan_to_num`. Additionally, flattening batch and view dimensions (`x_views.reshape(B * V, ...)`) before passing them to the shared encoder eliminates slow Python loops and drastically improves parallel GPU execution for multi-view processing.
**Action:** Always prefer vectorized dimension merging over Python loops for multi-view operations. When warping grids, use `float32`, `bmm` for batch processing, and leverage native function properties (like zero-padding for out-of-bound coordinates) instead of adding manual fix-up operations.
