## 2024-06-28 - Optimizing PyTorch Perspective Warping
**Learning:** When executing PyTorch grid sampling and perspective warping functions across multiple views, memory accesses can bottleneck calculations. Using explicit point-by-point logic with loops or masks (e.g. `torch.nan_to_num`) and calculating coordinates in `float64` is unnecessarily slow. Downcasting math to `float32` and processing the inverse projective homography via `torch.bmm` is highly performant. Fast invalidation of boundary coordinates avoids complex masked assignments by using simple conditionals (`torch.where`) mapped onto padding constraints natively supported in `F.grid_sample`.
**Action:** When implementing PyTorch geometry transformations and inverse homographies, aggressively use `torch.bmm` and `float32` arithmetic. To invalidate coordinates reliably, utilize `torch.where` or boolean indexing to assign out-of-bounds constants (e.g. `2.0` on normalized grids) over using full `torch.nan_to_num` passes.
