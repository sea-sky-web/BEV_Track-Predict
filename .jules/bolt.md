## 2024-05-19 - PyTorch Grid Sampling Coordinate Arithmetic Optimization
**Learning:** In PyTorch multi-view geometry pipelines, when mapping projections onto a target BEV space, pushing invalid coordinates (e.g. coordinates that fall out of the projection frustum or lie behind the camera Z <= 0) to out-of-bounds representations (like setting `x_norm` and `y_norm` to 2.0) explicitly through logical masks is significantly more computationally efficient than mathematically complex operations or padding operations like `torch.nan_to_num`. Also, using `torch.bmm` over `.unsqueeze(0).expand()` for coordinate projections on large matrices avoids hidden memory transfers.
**Action:** When working on PyTorch grid sampler inputs or geometric projection methods (e.g., `warp_perspective_torch`), always try to explicitly mask or push invalid coordinate targets out-of-bounds (which defaults to grid_sample padding) directly via fast logic instead of letting complex arithmetic handle edge conditions and running cleanup operations later. Use float32 coordinate arithmetic over float64 when doing projection and spatial transformation calculations for large performance speedups. Use `torch.bmm` instead of `.unsqueeze(0).expand()` when doing coordinate transformation and mapping.
