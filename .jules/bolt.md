## 2024-06-20 - Faster Grid Sampling using float32 and Padding Mode
**Learning:** In `warp_perspective_torch` and `create_grid_sampler`, grid generation and perspective transformation coordinate arithmetic done in `float64` is an unnecessary bottleneck. Downcasting these coordinates calculations to `float32` and substituting element-wise matrix multiplications for `torch.bmm` improves CPU and GPU inference times. In addition, using manually calculated masks and penalties for invalid, out-of-bound Z coordinates is slower and more complex than actively pushing the invalid coordinates sufficiently out of bounds and natively letting PyTorch's `F.grid_sample`'s `padding_mode="zeros"` return a padded feature space safely.
**Action:** When implementing spatial-warp features using `torch.bmm` combined with `grid_sample`, opt to aggressively use valid out-of-bounds pushing mechanisms (e.g., `invalid = z <= 1e-6`, mapped to a coordinate `2.0` representing completely out-of-bounds space) to safely zero-pad edge features rather than utilizing manual matrix-maskings and `nan_to_num` fills.
