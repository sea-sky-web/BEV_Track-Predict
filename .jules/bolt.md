## 2025-06-15 - [Geometry Projection Optimization]
**Learning:** In PyTorch, naive element-wise operations and coordinate normalizations inside a large grid loop like `warp_perspective` or `create_grid_sampler` (when creating `grid` for `grid_sample`) become significant bottlenecks due to kernel dispatch overheads. Pre-calculating scalar constants and replacing manual index handling (using `float64` tracking complex valid masks mapping back to indices) with native `float32` matrix batch multiplication `torch.bmm` on homogeneous coords significantly improves iteration time. Furthermore, leveraging `grid_sample`'s native capability to return zeroes for out-of-bounds coordinates instead of calculating boolean valid maps to conditionally mask is a massive speedup (`z <= 1e-6` pushing coords to `2.0` automatically invokes padding mode).
**Action:** Always prefer `float32` over `float64` for grid and perspective projection math where single-pixel strict accuracy isn't critically lost. Replace looping matrix multiplication or `@` operator across batches with `torch.bmm`. Push out-of-bounds masking to the lowest layer (`grid_sample` padding behavior) rather than implementing complex `torch.nan_to_num` masks explicitly.
