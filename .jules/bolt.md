## 2024-05-15 - Vectorize Multi-View Processing in Forward Pass
**Learning:** In the multi-view BEV projection model (`MVDetLikeNet`), processing views with a sequential Python for-loop creates unnecessary CPU overhead and fails to fully exploit GPU parallelism. Reshaping the batch and view dimensions into a single flattened dimension allows standard CNN operations (backbone, head) and PyTorch's `F.grid_sample` (used in `warp_perspective_torch`) to process all views simultaneously.
**Action:** When working on PyTorch multi-view or multi-camera architectures, always flatten the `(B, V, ...)` dimensions to `(B*V, ...)` before passing data through independent feature extractors or parallelizable ops like geometric projections, and reshape back afterward. This architectural pattern maximizes GPU utilization and should be the default approach.
