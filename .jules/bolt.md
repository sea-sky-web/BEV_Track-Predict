## 2024-06-09 - PyTorch Grid Sampling Performance Optimization
**Learning:** In PyTorch, using `float32` instead of `float64` for grid and coordinate arithmetic significantly boosts performance without measurable loss of precision for spatial projections. Furthermore, `grid_sample` natively zero-pads out-of-bounds coordinates, meaning complex bounds-checking logic and mask-filling using `torch.nan_to_num` are slow anti-patterns.
**Action:** When working with PyTorch spatial transformations and grid samplings, prefer `torch.float32`, use `torch.bmm` over `@` for batched matrix ops, and deliberately push invalid coordinates out-of-bounds `>1.0` or `<-1.0` (e.g., `invalid = z <= 1e-6; coords = torch.where(invalid, 2.0, coords)`) so that `grid_sample` handles padding automatically, avoiding custom masking penalties.
