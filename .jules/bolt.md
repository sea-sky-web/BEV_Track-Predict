
## 2026-07-03 - [PyTorch `warp_perspective_torch` Float32 & BLAS Optimization]
**Learning:** Downcasting coordinate calculations from `float64` to `float32` and leveraging `torch.bmm()` for explicitly calculating target coordinate transforms creates significant speedups in `grid_sample` generation routines without degrading coordinate mapping accuracy. In addition, replacing heavy `torch.where` clamp boundaries with `grid_sample`'s native bound handling (`padding_mode="zeros"`) and safely assigning invalid Z coordinates into out-of-bounds space naturally clips the values without unnecessary scalar operations.
**Action:** When implementing spatial mapping functions, avoid using `.clamp_()` boundaries if PyTorch operations handle bounds out-of-the-box (like `grid_sample` padding mode). Use `float32` precision arithmetic for meshgrid generation and take advantage of native batched matrix multiplication (`torch.bmm`) in place of explicit loops when reshaping coordinate indices.
